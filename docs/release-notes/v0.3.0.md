# SRW v0.3.0

v0.3.0 is a minor release: several of its changes need a look before or after the upgrade.
Read [Upgrading from 0.2.1](#upgrading-from-021) first; the section "Operator action required"
further down has the full text of each change.

## Highlights

- **`srw`, a command-line client.** Keep experts, connectors, workspace templates and projects
  as files, and run work from a terminal or a pipeline: `srw apply -f experts/`,
  `srw run "…" --wait`, `srw logs`, `srw cp`. It is one program for Linux, macOS and Windows,
  released with the platform as archives with checksums and build provenance, and as the image
  `ghcr.io/superhuman-remote-worker/srw-cli`. Exit codes say how a job ended, so a pipeline can
  act on them. Install it with
  `curl -fsSL https://docs.superhuman-remote-worker.com/install.sh | sh`, then read
  [srw CLI](https://docs.superhuman-remote-worker.com/cli/) and the
  [reference](https://docs.superhuman-remote-worker.com/cli-reference/).
- **Configuration as files no longer needs an admin token.** Two new token scopes that any
  user can tick under **Settings → API Keys**: `resources:write` applies and deletes manifests
  in your own account and in projects you can edit, and `projects:write` covers projects. The
  shared catalog stays with admins. An existing `jobs:read` token can now also validate, preview
  and export manifests. See the
  [scope table](https://docs.superhuman-remote-worker.com/api/#scopes).
- **Agents make and edit images.** Once an image model is pinned (by an admin under
  **Admin → Models → Defaults**, or by a user as their own default), jobs and sessions get
  `generate_image`: it generates or edits an image with that model, saves it in the workspace
  with its prompt, and shows the agent the result. Paid models count against a limit per job or
  session (20 by default). Agents also look closer at images (`read_file` with a region crops
  at full resolution), put several into one labelled sheet (`compose_images`), and a new image
  skill carries the method for decks, posters, character sheets and storyboards. In a session,
  the images you sent keep a small preview after a reload.
- **Try the app an agent built, beside the chat.** A Session's Canvas has a shared browser: the
  browser in the Session's workspace, shown live. Ask the agent to build a web app and it runs
  the app in its workspace, checks it in that browser and puts it on the Canvas for you. Choose
  **Take control** to click and type yourself and **Release control** to hand it back. The page
  is drawn at the size of the pane, or at a phone, tablet or desktop size. It needs a Container
  workspace or a VM on the same cluster as SRW; Jobs have no Canvas. See
  [Concepts](https://docs.superhuman-remote-worker.com/concepts/#the-canvas-and-the-shared-browser).
- **MCP connectors speak the 2026-07-28 protocol,** and fall back to the earlier handshake for
  servers that do not. A server can now ask a question while a call runs, such as "Spend 12
  Buzz to run this?". Each MCP connector says what happens then: decline (the default) or
  accept. A session whose permission mode asks you before it acts shows you the question as a
  card instead of declining. Two new tools serve every
  remote server that offers resources: `read_mcp_resource` shows one and `save_mcp_resource`
  writes it into the workspace, at full size where the server names an original.
- **A job plans in phases only when its expert says so.** There is one kind of job. Most start
  from the task, work with their tools and finish with one completion. An expert meant for long
  work has **Plans in phases** on and plans, works through to-dos and reviews its result; the
  bundled Developer, Scholar, Curator, Designer, Bughunter, Product QA, Critic and Receptionist
  do. One job can override its expert with `phases`. See
  [Concepts](https://docs.superhuman-remote-worker.com/concepts/).
- **Office deliverables.** The full workspace image now carries LibreOffice and a Python data
  and office stack, and six skills cover what people ask for most: a PDF report, charts, data
  analysis, a spreadsheet, a document and slides. Each visual one renders its output and has the
  agent look at it before delivering. The General Worker delivers the format you asked for
  instead of a Markdown file. Bundled skills now reach every installation; before, a release
  install saw none unless a chart switch was on.
- **More works without a grant.** A user's own agent gets the shell, subagents and VM
  workspaces by default, a user may run a job at full autonomy, and the Assistant runs commands
  once its workspace has a shell. A job at full autonomy now also applies its own changes to the
  project's cloud folder instead of waiting for a review nobody is watching for. Admins can set
  each of these back under **Admin → Capability Grants**.
- **Jobs have names, and Create Job asks for one text.** A job is listed by a title you can
  change from its row without changing its task. A job you start with a longer task is named by
  your auxiliary model a few seconds after you create it, as a session is. The create form has
  one task box that takes the text and the attached files, with Create Job beside it.
- **The expert editor and the connector pages are rebuilt.** The expert editor is a profile and
  six sections that open, with Save always in view. A project's Connectors tab is one list in
  two groups, with a picker to link, and the catalog separates the connectors SRW keeps from the
  ones people made. An expert no longer has Strategic and Tactical prompt fields; the phase
  method lives in skills.
- **DeepSeek models work as their provider intends.** They get their earlier reasoning back on
  every request, summarize their own context so that the provider's cache serves most of it,
  receive their output limit under the name they honour, and DeepSeek V4.1 Flash sees images. After any compaction
  that drops the opening message, a job is sent back to its brief.
- **Operations.** Admins are notified when no chat executor takes queued messages, Capacity
  warns about the stalled pool, and the waiting message says chat is down instead of "busier
  than usual". A stalled dispatcher is logged and can restart its replica. Every model call is
  recorded as it went out, failed and rejected ones too, and the audit writer survives a
  database restart.
- **A paused job says why.** When a job loses its workspace, the Jobs list and the job panel
  show the cause under **Why it is paused**, with what was kept (files on the persistent volume,
  the job's saved progress) and what is gone (running processes, `/tmp`). A workspace stopped
  for using more memory than its limit says so and names the limit, and the next Resume runs the
  job once with twice that limit. Without persistent volumes (the chart default), Resume now
  continues such a job on a new workspace and clones the job repository into it again; before,
  it answered 409 every time and the job could only be cancelled. A job whose last report the
  server could not process says so,
  and its owner and the project's officer are told; before, Resume answered "completion
  finalizing" and nothing on the job said why.
- **Cockpit.** Dictation works on phones again, with a new recording strip that fits any width.
  Chat display choices (reasoning blocks, tool calls, reading width, text size) moved to
  **Settings → General**.

## Upgrading from 0.2.1

Before the upgrade:

- **Copy any Strategic or Tactical prompt text you want to keep** out of the expert editor. A
  migration deletes these two fields from every expert.

After the upgrade, check what applies to you:

- **Grants are wider by default.** Non-admin users get shell tools, delegation, VM workspaces,
  agent-written experts, skills and automations, autonomous sessions and full-autonomy jobs
  without a grant. On an installation shared with people you do not trust, set the global grants
  back under **Admin → Capability Grants**; the operator action list names each one.
- **A full-autonomy job writes to the project's cloud folder without a review.** To keep the
  review for a project, set its folder copy to read-only or limit the autonomy its members may
  choose.
- **Jobs on General Worker, Engineer, Writer or a custom expert no longer plan in phases.** Set
  `phases: true` on the expert, or pass it for one job, to get the planned procedure back.
- **A project's knowledge base follows the connector list.** A job, session or live automation
  created with an explicit connector list runs without the project's knowledge base unless the
  list names that connector. Add it to API calls, manifests and automations that should keep it.
- **The Python package no longer installs a command named `srw`.** Install the client, or call
  `python -m orchestrator.operator_cli.manifest_resources`. The client has no default server
  (set `SRW_API_URL` or run `srw login`) and uses your proxy settings.
- **The full workspace image is about 810 MB larger**, for the office stack.
- **The image tool appears only after an image model is pinned.** Nothing changes for an
  installation without one.
- **The shared browser is on by default.** Sessions on a Container or a same-cluster VM show
  **Open browser** in the Canvas, which starts Chromium in the workspace and streams it to the
  Cockpit. Set `canvas.sharedBrowser.enabled: false` to hide it.
- **The server writes into VM workspaces by default.** The chart value
  `orchestrator.vmRemoteOperationProtocol.enabled` is now `true`: uploads into a VM, Canvas
  saves of a VM file, IDE settings and cloud staging into a VM work, where before they were
  refused and VM files on the Canvas showed view-only. The switch is one-way: once on, do not
  roll back to an image older than 0.2.0. Set it to `false` to keep VM workspaces read-only
  for the server.
- **A job whose workspace ran out of memory gets more on its next Resume.** That Resume runs it
  with twice the memory limit, once per job, up to the new chart value
  `workspace.memoryGrowth.max` (`16Gi`). Only the limit grows, not the request, so a node can be
  over-committed further than your workspace templates say. Set the value to `""` to switch
  this off.
- **No job stops after 5,000 tool calls any more.** The per-job tool-call limit is off by
  default, like the other limits on a job's own work; a job that reached it was parked for
  review. To keep it, set `limits.max_tool_calls_per_job: 5000` on the expert.
- The chart value `agent.skillsDbEnabled` is gone; a leftover in your values is ignored.
- Ten database migrations run at orchestrator startup, as usual.
