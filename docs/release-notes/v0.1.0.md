# SRW v0.1.0 — public beta

v0.1.0 is the first public release of SRW. It is a beta: read the
[security model](https://docs.superhuman-remote-worker.com/security-model/) before you connect
valuable systems. From this version on, the version number tells you whether an upgrade needs
your attention.

## What SRW is

A self-hosted runtime for AI work. You combine three building blocks: an expert (prompt, model,
tools), a workspace (none, files in your object store, a throwaway pod, or a VM) and connectors
(repositories, databases, cloud folders, email, MCP servers, knowledge bases). SRW runs them on
your own Kubernetes cluster as a live session or an autonomous job.

## Highlights

- **Install from a generator.** [superhuman-remote-worker.com/configure](https://superhuman-remote-worker.com/configure)
  writes the values, Secrets and an install script for a fresh k3s node or an existing cluster.
- **One model key is enough.** One OpenRouter API key covers all four model roles (chat,
  auxiliary, embedding, rerank), and both the generator and the local example seed them. See
  [Models](https://docs.superhuman-remote-worker.com/models/).
- **Documentation site.** [docs.superhuman-remote-worker.com](https://docs.superhuman-remote-worker.com/)
  has getting started, concepts, guides, troubleshooting and a Helm values reference generated
  from the chart.
- **Release notes and a versioning policy.** Every release now gets notes like these. Before
  1.0, a minor version means an operator must act; a patch is a drop-in `helm upgrade`. See
  [Versioning and upgrades](https://docs.superhuman-remote-worker.com/versioning/).
- **Attach and dictate on New chat.** Files and dictation work on the New chat screen before the
  session exists, and go with the first message.
- **The agent's shell has the image's tools.** In a workspace shell, Playwright finds the bundled
  Chromium, and `pip install` and `npm install -g` work for the agent.
- **Every bundled expert can load skills.** `use_skill` is its own tool category, so an expert
  that writes its own tool list keeps it. Eight bundled experts had lost it that way.

## Upgrading from 0.0.x

- The chart and image names are unchanged: `helm upgrade` with `--version 0.1.0`. First read
  **Operator action required** in the
  [GitHub Release](https://github.com/superhuman-remote-worker/srw/releases/tag/v0.1.0): the API
  now refuses ID tokens and other clients' tokens, and two chart defaults changed.
- **A model id names one catalog row.** If two providers held the same id, the upgrade keeps the
  bare id on the row SRW already routed to and renames each other row to `<id>-<provider>`, which
  keeps sending the old name upstream as its served model id. Routing does not change. An
  `llm.seed` entry whose id another provider holds is now skipped, with a log line saying why:
  give it its own `id` and set `servedModelId`.
- **A 3072-dimension embedding model never works.** If Settings → Models lists
  `openrouter/openai/text-embedding-3-large` (which `python init.py` added for an
  OpenRouter-only key), disable it and use Qwen3 Embedding 8B. SRW stores 4096-dimension vectors.
- **Custom workspace images:** the agent's SSH sessions don't inherit Dockerfile `ENV`. After
  your `ENV` lines, add `RUN /usr/local/bin/write-agent-environment NAME ...` with the names you
  set. The base images no longer set `PIP_TARGET`, so pip run as root installs system-wide
  without unsetting it. See
  [Workspace images](https://docs.superhuman-remote-worker.com/workspace-images/).
- **Idle job Pods:** with `orchestrator.workspaceCleanupReconciliationEnabled: true`, a job left
  paused, in review or waiting for a reply now releases its workspace Pod after 24 hours and keeps
  its volume; the next resume recreates the Pod. `workspace.idlePodReleaseSeconds: 0` turns this
  off. Installs with the flag off (the default) are unchanged.
- Pin `~0.1.0` to receive drop-in patches only.

## Known limitations

- Beta: run it single-tenant, for users you trust, and start with disposable data.
- Embedding models must produce 4096-dimensional vectors. Readiness does not check the size yet,
  so a wrong model shows up only as errors in the orchestrator log.
- Agent pods have no egress NetworkPolicy by default (`agent.networkPolicy.enabled: false`);
  workspaces do.
