# SRW v0.1.1

v0.1.1 is a patch release: `helm upgrade` with `--version 0.1.1` and your existing values. It
collects the fixes from the first week of the public beta. Nothing in it needs operator action;
read [Upgrading from 0.1.0](#upgrading-from-010) for two things you will notice.

## Highlights

- **A first install is easier to get right.** [Getting started](https://docs.superhuman-remote-worker.com/getting-started/)
  now names the certificate warning of a self-signed install, says that the images are built
  for linux/amd64 only, and describes the installer form's **Preconfigure model access** option,
  which seeds a chat model, an embedding model and a reranker from one OpenRouter key so the
  first login is ready for work. The login page's **Register** link no longer leads to a dead
  end: Keycloak asks a new user to verify their email only when the install can send mail.
- **Jobs start and finish more reliably.** The first strategic todo is derived from the
  opening message, a lifecycle tool completes the one todo still pending, and the no-tool-call
  and empty-response breakers end the job instead of letting it spin. A binary deliverable
  passes `job_complete` by its byte size, a shell command that ends its own shell no longer
  pauses the job, and a stopped job's duration ends when its work did.
- **Project officers hold their post.** A recycled or killed officer pod comes back instead of
  stranding the officer, a stuck-completion alarm no longer wakes every officer every
  30 seconds, one job completion wakes the officer once, and hold, release and conference
  notices reach him again. The conference brief tells the officer what was agreed, and the
  officer post can be run from MCP. See
  [Project loops](https://docs.superhuman-remote-worker.com/project-loops/).
- **Project deletion is safe.** A refused project delete no longer wipes the project's vault,
  a manifest delete runs the full project delete, and a decided delete always finishes.
  Members get a project's Gitea repositories back when they open it.
- **The knowledge base keeps its links.** A write finds a note wherever it lives in the vault,
  a link to a note that is not written yet becomes a graph edge once it is, a deleted project's
  notes leave the Neo4j graph, and an unconfigured Neo4j turns the graph projection off instead
  of logging errors.
- **The MCP server's OAuth is sturdier.** The authorization server sends codes only to
  allowlisted redirect URIs, connections refresh instead of expiring, an orchestrator outage is
  not a logout, the consent page says who is asking and where the code goes, and the server's
  state survives a rollout on a small persistent volume.
- **Cockpit.** The model catalog switches to cards before the table squeezes on a narrow
  screen, a cited workspace document opens from its chip and from the citations list, stacked
  citation handles all render as chips, and a job's Gitea link names the repository's real
  owner.
- **Usage metering.** Dash-versioned Claude model ids are priced against OpenRouter's dotted
  names, and a repriced call is counted once.

## Upgrading from 0.1.0

- **The MCP server gets a 512 MiB ReadWriteOnce volume** for its OAuth state
  (`mcp.persistence`, on by default). It needs the default `mcp.replicas: 1`; a chart with
  more MCP replicas refuses to render until you set `mcp.persistence.enabled: false`.
- **Email verification follows your mail settings.** On an install without `email.enabled` and
  `email.smtp.host`, the realm's `verifyEmail` flag turns off at the next Keycloak start, so a
  new registration no longer waits for a mail that cannot be sent. Admin approval of new users
  is unchanged.
- Three database migrations run at orchestrator startup, as usual.
